# ALTRun Next v0.6.0 RC Validation

This checklist is the release gate for v0.6.0-rc.1 and the basis for promoting the same frozen contract to v0.6.0 Stable.

## 1. Clean portable install

1. Extract the x64 package to a new directory that has never contained ALTRun Next data.
2. Start ALTRunNext.exe and confirm the launcher starts normally.
3. Confirm a schema-4 settings file is created with the published defaults.
4. Confirm the default Primary hotkey works, Secondary remains disabled, F2 opens Settings, Ctrl+Enter is the current-file-manager action and Ctrl+Shift+C copies the selected target.
5. Confirm Everything is disabled by default.
6. Exit and restart once; defaults and generated data must remain readable.

## 2. Upgrade matrix

Validate representative user profiles from:

- v0.5.0 (settings schema 3) -> rc.1
- v0.6.0-alpha.5 (settings schema 3) -> rc.1
- v0.6.0-alpha.6.1 (settings schema 4) -> rc.1
- v0.6.0-beta.1 (settings schema 4) -> rc.1
- v0.6.0-beta.2 (settings schema 4) -> rc.1

For schema-3 profiles, confirm migration to schema 4 preserves existing Primary/Secondary hotkeys, providers, behavior and appearance. If a legacy Primary chord conflicts with a new optional launcher-local default, the established user binding wins and the optional action is disabled.

For schema-4 profiles, opening the profile must not trigger another migration or silently replace custom bindings/settings.

## 3. Downgrade protection

After rc.1 has produced or saved schema-4 settings, open the same profile with a schema-3 build such as v0.5.0 or alpha.5. It must report newer-schema/read-only behavior and must not overwrite, normalize or downgrade the schema-4 file.

## 4. Smart Actions and Diagnostics regression

Repeat the beta real-world matrix:

- Explorer local, Unicode, spaces and UNC paths.
- Windows Open/Save dialog folder navigation.
- Total Commander left/right panels, Unicode/spaces and UNC where available.
- {folder} context.
- Direct URL and {query} Web actions.
- Copy/clip text actions and Ctrl+Shift+C selected-target copy.
- Diagnostics page context reporting.
- Everything running -> stopped -> restarted without restarting ALTRun Next.

No action semantics should differ from beta.2.

## 5. Hotkey Registry regression

- Windows-global bindings report registration state.
- Launcher-local bindings report launcher readiness.
- Valid custom bindings persist across restart.
- A failed Windows global registration keeps the previous working binding active.
- No duplicate/conflicting enabled chord is silently accepted.
- Frozen action IDs remain:
  - launcher.activate
  - launcher.activateSecondary
  - launcher.openSettings
  - result.navigateCurrentFileManager
  - result.copySelectedTarget

## 6. Package and platform gate

Both x64 and ARM64 artifacts must pass CI packaging. x64 packaged runtime startup must pass. Windows 10 API baseline and Windows desktop/runtime smoke must pass. Release ZIPs must contain only the package allowlist, no unexpected DLLs, and must report VERSION 0.6.0-rc.1 with Windows fixed FileVersion/ProductVersion 0.6.0.200.

The immutable v0.6.0-rc.1 tag, dev-latest and the successful main HEAD must point to the same commit, and corresponding release asset SHA-256 digests must match.
