# v0.7 Beta Desktop Validation

This checklist is the manual release record for the frozen v0.7 shortcut/workflow surface. Automated CI is required before desktop validation, but does not replace the real Windows checks below.

## Baseline

Test the packaged x64 build on Windows 11 first. Repeat compatibility-sensitive checks on Windows 10 when preparing RC.

Do not delete the existing portable `data/` directory for upgrade testing unless the case explicitly requires a clean profile.

## 1. Native update: alpha.9.4 -> beta.1

Start from a working packaged `v0.7.0-alpha.9.4` directory with real shortcuts/settings/usage.

- [ ] Development channel reports `v0.7.0-beta.1` as newer.
- [ ] Stable channel does not offer an older stable build as a downgrade.
- [ ] When the latest stable predates update-manifest.json, Stable channel reports the older stable version without surfacing HTTP 404/system error.
- [ ] Download completes and SHA-256 verification succeeds.
- [ ] Apply exits the old ALTRun Next process.
- [ ] `Update.exe` performs staged apply and launches beta.1.
- [ ] Post-update health confirmation succeeds; no rollback is triggered.
- [ ] `data/settings.json` remains schemaVersion 7.
- [ ] `data/commands.json` remains schemaVersion 2.
- [ ] Shortcut data, aliases, runtime-input modes and custom icons are preserved.
- [ ] Usage history is preserved.
- [ ] Provider states and custom Hotkey Registry bindings are preserved.
- [ ] `data/update` does not retain stale staging/backup state after success.
- [ ] Package contains `ALTRunNext.exe`, `Update.exe`, `Uninstall.exe`; no `ALTRunNext.Updater.exe`.

## 2. Shortcut Manager / Editor

- [ ] Open Shortcut Manager from tray and launcher context entry points.
- [ ] Local filter matches name, primary keyword and aliases.
- [ ] Add a shortcut using comma-separated primary keyword + aliases.
- [ ] Edit and save without losing aliases, target, arguments, working directory, type, runtime input or icon.
- [ ] Expanded Advanced options show a visible localized Working Directory browse button label and the picker still works.
- [ ] With Advanced collapsed, repeatedly switch Runtime Input among No extra input / Pass through / URL encode; Test input and bottom action buttons repaint cleanly with no stale horizontal line.
- [ ] With Advanced expanded, repeat the Runtime Input switching; Fixed arguments, Working Directory, Icon, administrator checkbox and bottom actions never overlap, duplicate or leave paint trails.
- [ ] Repeated Advanced expand/collapse after Runtime Input changes also repaints cleanly.
- [ ] Keyword/alias conflict detection rejects conflicts against all existing shortcuts.
- [ ] Delete requires the expected confirmation and removes only the selected shortcut.
- [ ] Test action runs the selected shortcut without changing persisted fields.
- [ ] Discovered result -> Add as shortcut opens pre-filled editor data.

## 3. Runtime Input

Create or reuse both Raw and URL-encoded shortcuts.

- [ ] `{input}` Raw preserves spaces and non-ASCII text as the launched argument/template expects.
- [ ] URL-encoded mode percent-encodes UTF-8 input.
- [ ] Empty required runtime input does not accidentally execute an invalid template.
- [ ] Fixed arguments and `{folder}` substitution still compose correctly with runtime input.
- [ ] Legacy schema-1 URL `{query}` migration remains usable after beta upgrade.

## 4. Path Conversion / Portability

Use paths containing spaces and non-ASCII characters.

- [ ] Target absolute -> portable relative conversion previews correctly.
- [ ] Working Directory absolute -> portable relative conversion previews correctly.
- [ ] Custom Icon absolute -> portable relative conversion previews correctly.
- [ ] Known Windows paths can use environment-variable form where supported.
- [ ] Reverse expansion resolves relative/environment paths correctly at runtime.
- [ ] URL and UNC targets are not incorrectly rewritten.
- [ ] Applying multiple checked conversions is atomic.
- [ ] Moving the whole ALTRun Next directory still allows converted shortcuts to work.

## 5. Result Icons / Launcher performance

First test with Result Icons disabled, then enabled.

- [ ] Icons Off: rapid typing and result-page changes remain visibly smooth.
- [ ] Icons On: icons appear asynchronously without blocking query input.
- [ ] Stale icon completions do not attach to the wrong result after rapid queries.
- [ ] Missing/broken custom icons fall back safely.
- [ ] Repeated Settings / Shortcut Manager open-close cycles do not show obvious continuous memory growth.
- [ ] Fresh idle startup remains in the established low-memory range; investigate material regression rather than small allocator variance.

## 6. Context Actions / Windows integration

- [ ] Folder result Enter opens normally.
- [ ] Explorer activation context + Ctrl+Enter navigates the captured Explorer window.
- [ ] Open/Save/folder-picker context navigates only the validated captured dialog.
- [ ] Total Commander active-panel navigation targets the captured TC window/panel.
- [ ] `{folder}` resolves only from a real captured filesystem folder.
- [ ] Copy selected target hotkey copies the expected Unicode target.
- [ ] Launcher result and Shortcut Manager context menus expose only applicable actions.

## 7. Managed Everything lifecycle

### Managed installation enabled

- [ ] Managed client runs headless/no-tray.
- [ ] Owned Everything Service is Running + AUTO_START.
- [ ] File/folder search returns results.
- [ ] Normal ALTRun Next exit closes the managed client but leaves the Service running.
- [ ] Restarting ALTRun Next reconnects without UAC.

### Provider explicitly disabled

- [ ] Unchecking Everything requests UAC only for an ALTRun-owned managed service.
- [ ] Managed client exits.
- [ ] Owned Service stops and becomes DISABLED.
- [ ] Reboot does not restart that disabled Service.
- [ ] Re-enabling requests UAC, restores AUTO_START, starts Service and client, then restores search.
- [ ] Cancelling UAC keeps the prior provider state consistent.

### External Everything

- [ ] External standard Everything IPC can be used when selected/available.
- [ ] Disabling the ALTRun provider does not stop, disable, reconfigure or uninstall external Everything.

## 8. Native Uninstall

Test from copies of a portable directory.

### Preserve user data

- [ ] `Uninstall.exe` copies work to TEMP and requests elevation.
- [ ] Exact ALTRun Next instance closes.
- [ ] Owned managed Everything client/service are removed when present.
- [ ] External Everything is untouched.
- [ ] Application files, managed Everything and update runtime state are removed.
- [ ] User `data/` state remains for reinstall/recovery.

### Remove all data

- [ ] Same ownership checks apply.
- [ ] Entire portable application directory is removable after uninstall.
- [ ] Immediately after stopping Managed Everything, transient sharing/lock failures are retried and do not abort an otherwise healthy full remove.
- [ ] Full-remove deletes the installation tree entry-by-entry, so any failure reports the exact file or directory instead of only the installation root.
- [ ] If Explorer is currently viewing the installation directory or a child, choosing full removal does not move Explorer before UAC.
- [ ] After UAC approval, the normal-integrity uninstall broker releases the Explorer view only when the elevated TEMP worker reaches the final deletion phase.
- [ ] Cancelling UAC leaves the Explorer location unchanged.
- [ ] After the broker handshake, the original install-directory Uninstall.exe exits and the elevated worker removes the root without requiring a reboot.
- [ ] A locked regular file reports possible lock owner application/PID information through Restart Manager when available.
- [ ] If deletion still fails, the dialog reports the actual filesystem error and failing path rather than a stale Win32 error.
- [ ] Full-remove must complete synchronously; the installation tree is not deferred wholesale to the next Windows reboot.
- [ ] Success/failure completion dialogs are foreground/topmost so they are not hidden behind unrelated windows.
- [ ] No ALTRun-owned Everything process/service remains.

Also test when Managed Everything was never installed and when its provider is already disabled.

## 9. DPI / compatibility

- [ ] 100% scale: Launcher, Settings, Shortcut Manager and Editor remain usable.
- [ ] 125% scale: no clipping/overlap in the main v0.7 workflow.
- [ ] 150% scale: no clipping/overlap.
- [ ] 200% scale: no clipping/overlap.
- [ ] Mixed-DPI move between monitors does not break launcher/editor geometry.
- [ ] Windows 10 compatibility-sensitive shell/context behavior has no blocker before RC.

## Exit criteria

Beta.1 validation is complete when:

- [ ] No data-loss or schema migration defect exists.
- [ ] No ownership bug can stop/reconfigure/uninstall external Everything.
- [ ] Native update succeeds on a real alpha.9.4 profile.
- [ ] Native uninstall succeeds in preserve-data and full-remove modes.
- [ ] Runtime Input, Path Conversion, custom icons and context actions have no release-blocking defect.
- [ ] No material responsiveness/memory regression is observed with the default configuration.

Record defects as focused beta fixes. Do not add new v0.7 features after this freeze.
