# ALTRun Next v0.8.0 Beta Validation

This checklist is the release gate for the v0.8 Beta line. Beta is a product-freeze phase: no new product features, provider semantics, search/ranking algorithms, schema migrations, or intentional Classic/Modern visual redesigns are accepted unless a confirmed regression, compatibility issue, data-safety/security issue, or release blocker requires a narrowly scoped fix.

## Freeze baseline

- [ ] VERSION is `0.8.0-beta.3`.
- [ ] Windows FileVersion/ProductVersion is `0.8.0.10003`.
- [ ] Settings schema remains 11.
- [ ] Commands schema remains 2.
- [ ] Usage schema remains 2.
- [ ] Provider Cache schema remains 22.
- [ ] Classic assets and geometry match the accepted alpha.5.49 baseline.
- [ ] Modern Compact presentation and interaction match the accepted alpha.6.4 baseline.
- [ ] Per-result program/file icons remain intentionally absent.
- [ ] Smart numeric Quick Launch remains shared between Classic and Modern Compact.
- [ ] No synchronous filesystem, Shell, MSI, registry or provider-discovery work has been added to the ordinary search-keystroke path.

## Package and version identity

Validate both x64 and ARM64 artifacts produced by the same commit.

- [ ] `ALTRunNext-x64.zip` is present.
- [ ] `ALTRunNext-ARM64.zip` is present.
- [ ] `SHA256SUMS.txt` hashes match both archives for a tagged release.
- [ ] Packaged `VERSION` matches the source VERSION.
- [ ] `ALTRunNext.exe` fixed FileVersion and ProductVersion match `0.8.0.10003`.
- [ ] `ALTRunNext.exe`, `Update.exe`, and `Uninstall.exe` are present.
- [ ] `DESKTOP_VALIDATION.md` and `V0.8_BETA_VALIDATION.md` are present.
- [ ] No unexpected runtime DLL is present.
- [ ] cpp-pinyin remains statically linked; cpp-pinyin and miniz license files are present.
- [ ] A clean extracted x64 package reaches the packaged-runtime health signal.
- [ ] A repeat launch leaves idempotent shell integrations unchanged.

## Upgrade and data compatibility

Run with copies of representative data from v0.7 stable and v0.8 alpha builds.

- [ ] Existing `settings.json` upgrades without losing user choices.
- [ ] Existing `commands.json` preserves UUIDs, aliases, targets, runtime-input fields, administrator state, working directories and custom icons.
- [ ] Existing `usage.json` preserves global and query-scoped ranking evidence.
- [ ] Existing Provider Cache rebuild/compatibility behavior remains correct.
- [ ] Downgrade/newer-schema read-only protections still prevent destructive writes.
- [ ] Backup/self-healing behavior still recovers supported damaged config files.
- [ ] Moving the portable directory preserves data and repairs only ALTRun-owned path integrations.
- [ ] User data survives an application update.
- [ ] Preserve-data uninstall retains user settings, shortcuts and usage data.
- [ ] Full uninstall removes ALTRun-owned data only after the destructive confirmation.

## Launcher — Classic

Classic is frozen. Perform only regression validation.

- [ ] Global launcher activation repeatedly shows/hides without placement drift.
- [ ] Classic geometry and original assets are unchanged at 100%, 125%, 150%, 175% and 200% DPI.
- [ ] Rapid typing remains responsive.
- [ ] Up/Down and Tab/Shift+Tab navigation remains cyclic where specified.
- [ ] Enter executes the selected result.
- [ ] Successful execution remains silent.
- [ ] Search, pinyin, wildcard/path syntax, usage learning and Everything merge match the accepted alpha.5.49 behavior.
- [ ] `v2` / `v2r` numeric-intent arbitration remains correct with Everything enabled.
- [ ] Bare-number execution still works when continuation is confirmed absent.
- [ ] IME composition never causes unintended numeric execution.

## Launcher — Modern Compact

Modern Compact is frozen at the accepted alpha.6.4 visual/interaction baseline.

- [ ] Empty/no-result, 1-row, 6-row, 9-row and 10-row heights are correct.
- [ ] A pending Everything query does not visibly collapse and re-expand the shell.
- [ ] Stress the `10 -> 1 -> 10` result-count path with Everything pending.
- [ ] A surviving selected result remains selected when asynchronous results reorder.
- [ ] If the selected identity disappears, selection clamps to the nearest valid row instead of jumping to row 1.
- [ ] Mouse selection returns keyboard focus to the search edit so the next character refines the query.
- [ ] Tab/Shift+Tab/Up/Down navigation remains cyclic.
- [ ] Numeric hints map 1–9 and 0 to rows 1–10.
- [ ] Selected-row return affordance and footer Enter affordance render cleanly.
- [ ] Search glyph and Latin/CJK text remain sharp at 100%, 125%, 150%, 175% and 200% DPI.
- [ ] Long application aliases, file paths, UNC paths and root paths ellipsize without overlap.
- [ ] Windows 11 backdrop acceptance/rejection does not change layout or contrast.
- [ ] Windows 10 solid fallback remains deterministic.
- [ ] Rapid query/result transitions do not cause unrelated text or surfaces to flash.

- [ ] Enabling file/folder search starts or acquires only the intended ALTRun-managed runtime.
- [ ] Initial acquisition uses official stable metadata when available and verified fallback policy when it is not.
- [ ] Integrity verification occurs before managed archive promotion/use.
- [ ] The managed tray-icon preference appears only when ALTRun actually owns the live default IPC endpoint.
- [ ] Toggling the managed tray icon does not reinstall the service or mutate external Everything.
- [ ] Check for updates never silently upgrades an existing managed installation.
- [ ] Explicit Update Everything changes only the ALTRun-owned managed version.
- [ ] Disabling the source stops only the ALTRun-owned client lifecycle specified by the product.
- [ ] Application exit never terminates an external Everything process by name alone.
- [ ] Portable-directory moves repair stale ALTRun-owned service/runtime paths.
- [ ] Late/stale IPC replies never replace a newer query or trigger delayed execution.

## Beta.2 security / release hardening

- [ ] Update and Uninstall elevation no longer uses a predictable flat `%TEMP%\\ALTRunNext-*.exe` path.
- [ ] The temporary elevated worker lives in a cryptographically random dedicated directory and its file/directory guards remain held through UAC process creation.
- [ ] Cancelling UAC removes the unused temporary worker immediately.
- [ ] Successful/failed elevated workers schedule only their dedicated temporary worker directory for cleanup.
- [ ] Managed Everything install/start/repair/service-policy elevation retains the original executable path semantics while guarding the executable and containing directory through process creation.
- [ ] The managed Everything client remains portable under `data/tools/Everything`, but the persistent high-privilege Everything Service ImagePath points only to the protected service host under the real Program Files known folder (`Aspeternity/ALTRunNext/EverythingService/<version-arch>/Everything.exe`).
- [ ] A legacy ALTRun-owned portable service path migrates to the protected service host; a healthy external/user-managed Everything service is never retargeted, enabled, disabled or started by ALTRun.
- [ ] Service repair is bound to the exact managed source path locked by the normal-integrity parent for the full elevated-helper lifetime; the elevated helper does not rescan for a newer sibling source.
- [ ] Native update HTTP policy rejects HTTPS -> HTTP redirect downgrade.
- [ ] The verified archive remains available through the install handoff; Update.exe reopens it with write/delete sharing denied and re-verifies the release-manifest SHA-256 after the old process exits.
- [ ] When UAC is required, Update.exe re-extracts the verified archive into a random protected staging/work directory under the protected install root before any elevated replacement; the earlier user-writable staging tree is never used as elevated input.
- [ ] The protected work directory also contains the rollback backup; it is removed after success or complete rollback and retained with an error log if recovery is incomplete.
- [ ] Update rollback removes files/directories created by the failed transaction but never removes a directory that existed before the update.
- [ ] Update source/install reparse traversal is rejected and cannot write outside the portable root.
- [ ] The post-update health event is random per transaction and no longer uses a NULL DACL.
- [ ] Both automatic-main and explicit-tag release paths produce the same four assets: x64 ZIP, ARM64 ZIP, SHA256SUMS and update-manifest.
- [ ] A published SemVer tag cannot be force-moved or republished with different assets; only `dev-latest` remains movable.
- [ ] The public versioned `update-manifest.json` is byte-identical to the locally generated manifest before the release job succeeds.
- [ ] Non-release CI jobs run with read-only repository contents permission.

## Update lifecycle

Beta.3 review cases:

- [ ] A malformed primary commands/settings/usage JSON keeps its good backup; a partly valid primary with no backup exposes valid records read-only without overwriting source bytes.
- [ ] Corrupt ZIP members, path traversal, delayed writes and cancellation fail extraction before publishing a package; no partial managed Everything version becomes active.
- [ ] A modified or unsigned managed Everything source is rejected before promotion to the privileged service host; the official signed source still installs and repairs on x64 and ARM64.
- [ ] Rollback blocked by access denial or an occupied destination retains the only backup and reports its location; a running new process prevents unsafe rollback.
- [ ] Rapid successive launches keep search learning responsive, merge persistence, retry after temporary write failure, and flush the latest generation at exit.
- [ ] Provider discovery interrupted during file, registry and AppsFolder enumeration exits without publishing an incomplete snapshot.
- [ ] 1/100/1000/10000-entry searches with and without `{folder}` templates keep identical ordering and smart numeric launch behavior; record input latency and peak memory on Windows.

- [ ] Stable/Development update preferences persist across restart.
- [ ] Update preference toggles never trigger an immediate network check by themselves.
- [ ] Manual Check for updates remains asynchronous and cancellable.
- [ ] `0.8.0-alpha.6.4 -> 0.8.0-beta.1` is ordered as an upgrade.
- [ ] `0.8.0-beta.1 -> 0.8.0-rc.1` is ordered as an upgrade.
- [ ] Older/prerelease versions never replace a newer installed version.
- [ ] Development channel resolves the rolling `dev-latest` manifest.
- [ ] Package SHA-256 mismatch prevents staging/apply.
- [ ] Valid staging verifies VERSION and required executables before apply.
- [ ] Writable portable directories update without UAC.
- [ ] Protected directories elevate only the updater helper.
- [ ] Health failure restores the previous application files and relaunches the previous version.
- [ ] Successful health confirmation removes stale staging/backup state.
- [ ] User data and managed Everything data remain intact through update.
