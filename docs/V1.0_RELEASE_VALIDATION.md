# ALTRun Next 1.0.0 Release Validation

ALTRun Next 1.0.0 is promoted directly from the validated v0.8.0-beta.3 hardening line. The release intentionally skips a separate RC cycle. The accepted product behavior becomes the first stable 1.x baseline; later non-blocking defects are handled through 1.0.x maintenance releases.

## Frozen release contract

- Version: `1.0.0`
- Windows fixed FileVersion/ProductVersion: `1.0.0.30000`
- Settings schema: 11
- Commands schema: 2
- Usage schema: 2
- Provider Cache schema: 22
- Architectures: x64 and ARM64
- Main launcher surfaces: Classic ALTRun and Modern Compact
- Stable release channel: GitHub `latest` versioned release
- Versioned tag and release assets are immutable.

## Automated publication gates

The `v1.0.0` tag is allowed to publish only after the tag workflow passes all of the following:

- tag / VERSION identity verification;
- version metadata and release-contract verification;
- Core Release-mode test suite;
- Windows desktop/runtime smoke suite;
- Windows 10 API compatibility build and smoke suite;
- x64 and ARM64 production builds;
- exact portable-package allowlist and embedded executable icon checks;
- packaged x64 startup smoke;
- SHA-256 generation and verification for both ZIPs;
- generated `update-manifest.json` validation;
- immutable release publication checks.

## Interactive sign-off carried forward from the beta.3 closeout

The final beta.3 development cycle received real-Windows validation for the high-impact regressions addressed during closeout, including Settings navigation repaint behavior, the minimal portable ZIP structure, managed Everything acquisition/lifecycle behavior, and Uninstall cleanup after managed Everything use. The project owner accepted the current product state for direct 1.0.0 promotion and chose to handle later non-blocking bugs through maintenance releases.

This promotion does not claim that future defects are impossible. It records that no currently known issue is being treated as a 1.0.0 release blocker.

## Post-release policy

- Confirmed regressions, compatibility issues, data-safety/security fixes and packaging defects may ship as 1.0.x.
- Existing user data and schema compatibility remain protected unless a future release explicitly documents and tests a migration.
- Search/ranking and numeric-intent behavior should not be changed in a maintenance release without a specific reproduced defect and regression coverage.


## Asterun 1.0.1 maintenance validation delta

Asterun 1.0.1 is a focused maintenance update on top of the validated 1.0.0 baseline.

- Version: `1.0.1`
- Windows fixed FileVersion/ProductVersion: `1.0.1.30000`
- Settings schema: 11 (unchanged)
- Commands schema: 2 (unchanged)
- Usage schema: 2 (unchanged)
- Provider Cache schema: 22 (unchanged)
- Product/search/provider semantics: unchanged
- Visual delta: approved transparent Asterun app/tray icon set
- Reliability delta: Asterun now owns a product-specific tray GUID; startup hotkey conflicts are non-fatal and are reported once while the normal tray entry remains available for recovery.
- Automated regression: packaged x64 runtime smoke reserves the configured primary hotkey with `showTrayIcon=true`, confirms the single startup warning appears, dismisses it, requires the Asterun process to remain alive, and verifies the Asterun tray GUID is registered.
- Real-machine acceptance: pending owner verification before publishing the immutable `v1.0.1` tag.
